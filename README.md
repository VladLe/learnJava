# News Rewriter

Сервис, который автоматически собирает новости из RSS-лент, переписывает их с
помощью LLM (добавляя собственную ценность) и публикует результат в один или
несколько сайтов на WordPress. Управление — через **админ-панель**.

> **Статус:** реализованы этапы 0–6 и ядро этапа 7 из [плана](docs/ROADMAP.md):
> Django-проект, админ-панель, сбор RSS с дедупликацией, извлечение текста,
> рерайт (Anthropic/OpenAI), публикация в WordPress с изображением записи из
> стокового банка (Pexels), планировщик, метрики, переключение автопубликации
> и деплой (Docker + PostgreSQL). Логика покрыта тестами (`pytest`).
> Опционально (по мере роста нагрузки): Celery вместо in-process планировщика.

## Что делает сервис

Конвейер из пяти шагов, который работает по расписанию:

1. **Сбор** — периодически опрашиваем настроенные RSS-источники.
2. **Дедупликация** — отсеиваем материалы, которые уже обрабатывали.
3. **Извлечение** — достаём полный текст статьи (RSS часто отдаёт только анонс).
4. **Рерайт** — переписываем заголовок, тело и SEO-мета через LLM.
5. **Публикация** — отправляем готовый пост в WordPress через REST API, в нужную
   рубрику.

Между шагами всё состояние хранится в БД, поэтому конвейер устойчив к сбоям:
любой шаг можно повторить, не теряя прогресс.

## Админ-панель

Управление сервисом — через веб-интерфейс на базе **Django admin** под
пользователем-администратором. В админке можно:

- **Добавлять сайты WordPress** для публикации (адрес, учётные данные).
- **Добавлять RSS-ленты** (источники): URL, периодичность опроса, целевой сайт.
- **Указывать рубрику** на сайте, в которую попадают новости конкретной RSS-ленты
  (категории подтягиваются с самого сайта, выбор — из выпадающего списка).
- **Следить за конвейером**: статусы статей, ошибки, повтор упавших публикаций.

Подробности — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (раздел «Админ-панель»).

## Технологический стек

| Область | Выбор | Почему |
|---|---|---|
| Веб-фреймворк / админка | Django + Django admin | Встроенная админ-панель, пользователи и роли, ORM, миграции из коробки |
| Аутентификация | Django auth (суперюзер) | Готовый вход в админку, без своей реализации |
| БД / ORM | Django ORM + PostgreSQL (prod) / SQLite (dev) | Миграции Django |
| Планировщик | `django-apscheduler` | Задачи и история запусков видны в админке; на рост — Celery beat |
| RSS | `feedparser` | Стандарт де-факто для разбора лент |
| Извлечение текста | `trafilatura` | Достаёт основной текст статьи по URL |
| HTTP | `httpx` | Современный клиент с таймаутами и ретраями |
| Рерайт | Абстракция `RewriteService` (Anthropic / OpenAI) | Провайдер выбирается в настройках |
| Секреты | `django-environ` + шифрование полей | Ключи API — из env; пароли WP — шифруются в БД |
| Тесты | `pytest` + `pytest-django` | — |

## Запуск

### Локально (разработка)

```bash
pip install -e ".[dev]"
cp .env.example .env          # заполнить SECRET_KEY, FIELD_ENCRYPTION_KEY, ключи LLM
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver     # админка: http://localhost:8000/admin
```

Запуск конвейера и планировщика:

```bash
python manage.py run_pipeline                 # все источники, все шаги
python manage.py run_pipeline --step fetch    # только сбор
python manage.py run_pipeline --source-id 1   # один источник
python manage.py run_scheduler                # фоновый планировщик
```

Метрики конвейера — на странице `/admin/metrics/`.

### Продакшн (Docker + PostgreSQL)

```bash
cp .env.example .env           # DATABASE_URL=postgres://newsroom:newsroom@db:5432/newsroom
docker compose up --build      # web (gunicorn) + scheduler + postgres
```

Запуск тестов:

```bash
pytest
```

## Правовые и этические замечания

Автоматический рерайт чужих новостей затрагивает авторское право, поэтому
архитектура заложена так, чтобы работать чисто:

- **Только RSS / официальные API источников** — никакого скрытого скрейпинга.
- **Сохраняем ссылку на первоисточник** в каждой публикации.
- **Добавляем собственную ценность** (саммари, контекст, аналитику), а не просто
  перефразируем — это и юридически безопаснее, и лучше для SEO: поисковые системы
  понижают дублированный и «спинной» контент.
- **Уважаем `robots.txt` и условия использования** источников; отключаем источник
  в админке, если он это запрещает.

Перед запуском в продакшн рекомендуется проверить условия использования каждого
конкретного источника и при необходимости получить разрешение на републикацию.

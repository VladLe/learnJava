# План реализации

Поэтапный план: каждый этап даёт работающий результат, который можно проверить,
прежде чем двигаться дальше.

## Этап 0 — каркас проекта

- `pyproject.toml`, зависимости, структура пакетов из
  [ARCHITECTURE.md](ARCHITECTURE.md).
- `config.py` (pydantic-settings + загрузка YAML), пример `.env` и
  `settings.yaml`.
- `db.py`, `models.py`, инициализация Alembic и первая миграция.
- `pytest`, базовый CI.

**Проверка:** проект ставится, миграция создаёт таблицы, тесты запускаются.

## Этап 1 — сбор и дедупликация

- `sources/base.py` + `sources/rss.py` (feedparser).
- `dedup.py` (нормализация URL + хеш).
- Сохранение статей в статусе `fetched`, пропуск дубликатов.

**Проверка:** запуск по одному RSS-источнику наполняет таблицу `articles`,
повторный запуск не создаёт дублей.

## Этап 2 — извлечение текста

- `extract/article.py` (trafilatura) с обработкой ошибок.
- Переход `fetched → extracted` / `failed`.

**Проверка:** у собранных статей появляется `full_text`; недоступные/непарсимые
помечаются `failed` с причиной.

## Этап 3 — абстракция рерайта

- `rewrite/base.py` (ABC + DTO), `rewrite/factory.py`.
- `rewrite/anthropic.py` (структурированный JSON-ответ), затем
  `rewrite/openai.py`.
- Промпт с сохранением фактов, HTML-телом, SEO-мета и атрибуцией.
- Переход `extracted → rewritten`, запись `rewritten_content` с учётом токенов.

**Проверка:** для статьи генерируется корректный `RewriteResult`; смена
провайдера в конфиге не требует правок в конвейере.

## Этап 4 — публикация в WordPress

- `publish/base.py` + `publish/wordpress.py` (REST API, Application Passwords).
- Переход `rewritten → published`, запись в `publications`.
- По умолчанию публикация в `draft`.

**Проверка:** готовый пост появляется в WordPress как черновик с заголовком,
телом, тегами и ссылкой на первоисточник.

## Этап 5 — оркестрация и расписание

- `pipeline.py` (полный конвейер end-to-end по одному источнику).
- `scheduler.py` (APScheduler, задача на источник).
- `cli.py`: `run-once`, `run-scheduled`, `add-source`, `add-site`.

**Проверка:** `run-once` проходит весь путь от RSS до черновика в WP;
`run-scheduled` повторяет это по расписанию.

## Этап 6 — эксплуатация (по мере необходимости)

- Структурное логирование и метрики (число обработанных, ошибки, затраты
  токенов).
- Несколько источников и несколько сайтов.
- Переключение автопубликации (`draft → publish`) после оценки качества.
- При росте нагрузки — вынос конвейера в очередь задач (Celery/RQ), Postgres,
  контейнеризация (Docker).
- Опционально: подбор/генерация изображения записи, ручная модерация перед
  публикацией, дедупликация по содержимому (не только по URL).

## Принципы

- **Вертикальные срезы:** на каждом этапе — работающий, проверяемый кусок, а не
  «сначала вся инфраструктура».
- **Абстракции на границах:** источники, рерайтеры и публикаторы — за
  интерфейсами, чтобы добавлять новые без переписывания ядра.
- **Безопасный дефолт:** черновики и `draft`-публикация, пока не подтверждено
  качество рерайта.
